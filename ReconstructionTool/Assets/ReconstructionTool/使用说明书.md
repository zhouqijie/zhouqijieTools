# Unity 三视图稀疏重建工具使用说明书

## 1. 工具用途

本工具根据三张从不同位置、不同相机拍摄的照片，以及人工标记的一一对应参考点，恢复：

- 三台相机的拍摄位置和方向；
- 每台相机独立的像素焦距、水平 FOV 和垂直 FOV；
- 所有有效参考点的三维坐标；
- 依据用户指定距离恢复的绝对尺度；
- 整体、单台相机和单个参考点的重投影误差。

底层使用 PoseLib 2.0.5、Ceres Solver 2.2.0 和 Eigen 3.4.0。当前版本只生成相机和稀疏三维点，不生成稠密点云或网格。

## 2. 运行条件与限制

- Unity 版本：6000.3.15f1。
- 平台：Windows x64 UnityEditor。
- 固定使用三张照片和三个 `RefPicture`。
- 三张照片可以来自不同设备，分辨率、长宽比和 FOV 可以不同。
- 使用针孔相机模型，主点固定在图片中心，且 `fx = fy`。
- 不估计径向畸变、切向畸变、非中心主点和滚动快门。
- 不支持鱼眼原图。明显畸变的照片应先完成镜头校正。
- 不支持照片被非等比拉伸、未知裁剪或透视变形。
- 当前要求每个参考点都能在三张照片中标出。

## 3. 拍摄照片

### 3.1 拍摄要求

1. 三张照片必须拍摄同一个静止场景或静止物体。
2. 拍摄时应改变相机位置，不能只站在原地旋转相机。
3. 相机之间应具有明显但不过大的平移基线，并保持足够的共同可见区域。
4. 尽量避免运动模糊、失焦、过曝、强反光和透明表面。
5. 保留完整原图，不要对某一张照片单独裁剪或改变长宽比。
6. 如果必须缩放图片，应同时等比缩放整张图片，并让 Canvas 使用缩放后的真实像素尺寸。

一个比较稳定的拍摄方式是：一张正面照片，另外两张分别从左前方和右前方拍摄。物体表面应在三张图中都有足够多的共同可见点。

### 3.2 相机运动要求

以下拍摄方式容易导致失败：

- 三张照片几乎来自同一个位置；
- 只有旋转，没有平移；
- 相机基线相对于物体距离过小；
- 视角变化过大，导致共同可见点太少；
- 所有标记点都位于同一个平面。

## 4. 创建三个参考图片 Canvas

场景中必须恰好存在三个 `RefPicture`。

对每张照片分别执行：

1. 创建一个 Canvas。
2. 建议把 Canvas 的 Render Mode 设为 `World Space`，方便在 Scene 窗口中同时查看三张图片。
3. 将 Canvas 的 `RectTransform` 宽度和高度设为照片的实际像素宽高。
4. 在 Canvas 同一个 GameObject 上添加 `RefPicture`。
5. 在 Canvas 下创建 `Image` 或 `RawImage` 子对象，用它完整显示照片。
6. 将显示图片的子对象拉伸到 Canvas 全部区域，不要做非等比缩放。

例如：

| Camera ID | 照片尺寸 | Canvas RectTransform |
| --- | --- | --- |
| 0 | 4000 × 3000 | 4000 × 3000 |
| 1 | 1920 × 1080 | 1920 × 1080 |
| 2 | 3024 × 4032 | 3024 × 4032 |

Canvas 可以分别具有不同的 pivot、世界位置、整体旋转和等比缩放。工具会使用 `InverseTransformPoint` 把点转换回图片局部像素坐标。

> Canvas 在 Scene 中显示得很大时，可以整体等比缩小，例如把 Scale 设为 `0.001, 0.001, 0.001`。不要只缩放一个轴。

## 5. 配置 RefPicture

### 5.1 Camera ID

三个 `RefPicture` 的 Camera ID 必须分别为：

- 第一张：`0`
- 第二张：`1`
- 第三张：`2`

Camera 0 定义最终重建坐标系：

- Camera 0 的位置固定为世界原点；
- Camera 0 的旋转固定为单位旋转；
- 其他相机和三维点都相对于 Camera 0 输出。

### 5.2 垂直 FOV 搜索范围

每个 `RefPicture` 都有独立的：

- 最小垂直 FOV；
- 最大垂直 FOV。

默认范围为 `15°～120°`。如果完全不知道相机参数，可以先保留默认值。

如果能够从 EXIF、设备规格或经验中大致判断 FOV，可以适当缩小范围，例如估计 VFOV 在 50° 左右时设置为 `35°～70°`。更合理的范围可以减少歧义，但真实 FOV 必须处于范围内部，不能刚好卡在边界。

不要把手机厂商给出的对角 FOV 直接当作垂直 FOV。

## 6. 创建和标记 RefPoint2D

### 6.1 创建参考点

在每个 Canvas 下创建若干 UI 子对象：

1. 子对象必须具有 `RectTransform`。
2. 添加 `RefPoint2D`。
3. 设置整数 `Id`。
4. 将对象中心移动到照片中的目标位置。
5. 可以添加小尺寸 `Image` 作为十字、圆点或其他视觉标记。

同一个物理点在三张照片中必须使用完全相同的 ID。

例如，物体左上角在三张图中都使用 ID `100`，右下角都使用 ID `101`。

### 6.2 ID 规则

- 同一张照片内不能存在重复 ID。
- 三张照片的 ID 集合必须完全相同。
- ID 可以不连续，也可以使用负数，但建议使用容易管理的正整数。
- Camera 0 的尺度参考 ID 也必须存在于这个共同 ID 集合中。

### 6.3 点的数量

- 最少需要 8 个共同点。
- 少于 15 个点时工具会显示低稳定性警告。
- 通常建议使用 20～50 个高质量点。

数量不是唯一标准。点的准确性、空间覆盖和深度分布更重要。

### 6.4 选点建议

优先选择：

- 清晰、尖锐并且能精确重复定位的角点；
- 三张照片中都可见且未被遮挡的结构；
- 分布在图片四周和中心的点；
- 同时包含物体前部、中部和后部的非共面点；
- 能明确判断为同一个物理位置的细节。

避免选择：

- 大面积平面上没有明显特征的位置；
- 模糊轮廓或阴影边缘；
- 反光、透明或会随视角变化的位置；
- 重复纹理中容易混淆的点；
- 被遮挡后只能凭猜测标出的位置；
- 只有屏幕坐标相近、实际并非同一物理点的位置。

建议在放大照片后标点。少量高精度点通常优于大量随意标记的点。

## 7. 配置绝对尺度

绝对尺度只在 Camera 0 的 `RefPicture` 上配置：

- 参考点 ID A；
- 参考点 ID B；
- 两点的真实距离。

两个 ID 必须不同，且都存在于三张照片中。真实距离必须大于 0。

输出单位由填写的真实距离决定：

- 如果填写米，输出位置单位就是米；
- 如果填写厘米，输出位置单位就是厘米；
- 如果希望 1 Unity unit 表示 1 米，就应使用米填写距离。

建议选择：

- 实际距离较大；
- 能够准确测量；
- 两端容易在照片中精确定位；
- 不会因物体弯曲或遮挡产生歧义；
- 尽量不要选择两个非常接近的点。

## 8. 输入检查清单

点击 Solve 前确认：

- 场景中恰好有三个 `RefPicture`；
- Camera ID 正好为 0、1、2；
- Canvas 宽高等于对应照片像素尺寸；
- 照片没有被非等比拉伸或未知裁剪；
- 每张照片中的 ID 都不重复；
- 三张照片具有完全相同的 ID 集合；
- 至少有 8 个共同点，建议 15 个以上；
- 所有点都位于对应图片矩形内；
- 点具有明显的非共面深度；
- Camera 0 的尺度 ID 正确；
- 尺度真实距离和单位正确；
- 三张照片之间具有明显平移视差。

## 9. 执行 Solve

1. 在 Hierarchy 中选中任意一个带有 `RefPicture` 的 Canvas。
2. 在 Inspector 底部点击 `Solve`。
3. 无论在哪个 `RefPicture` 上点击，工具都会查找场景中的全部三个 `RefPicture`。
4. 尺度配置始终读取 Camera 0。
5. 输入验证和原生求解都成功后，工具才会创建新结果。

求解失败时不会删除或替换旧的 `ReconstructionResult`。

再次 Solve 成功时：

- 先完整求出新结果；
- 再替换旧结果；
- 整个替换过程可以使用一次 Unity Undo 撤销。

## 10. 输出层级

成功后生成：

```text
ReconstructionResult
├── Cameras
│   ├── CameraPoint_0
│   ├── CameraPoint_1
│   └── CameraPoint_2
└── Points
    ├── RefPoint_100
    ├── RefPoint_101
    └── ...
```

求解完成后，新生成的 `ReconstructionResult` 会被自动选中。

## 11. 查看求解结果

### 11.1 ReconstructionResult

根对象包含：

- `Reprojection RMS`：所有图片长边归一到 1000 像素后的整体重投影 RMS；
- `Scale Multiplier`：从无尺度解转换到指定真实距离时使用的倍率；
- `Median Triangulation Angle`：参考点的中值三角化角；
- `Solve Information`：原生插件版本和有效点数量。

判断建议：

- RMS 越低越好；
- 中值三角化角过小通常表示相机基线不足；
- 工具在三角化角低于安全阈值或误差过高时会直接拒绝结果；
- 数值通过校验并不代表点一定具有正确物理含义，仍应在 Scene 中检查相机和点云形状。

### 11.2 CameraPoint3D

每个相机对象包含：

- `Camera ID`：0、1 或 2；
- `Source Picture`：对应的 `RefPicture`；
- `Focal Length Pixels`：恢复出的像素焦距；
- `Horizontal Fov`：水平 FOV，单位为度；
- `Vertical Fov`：垂直 FOV，单位为度；
- `Reprojection RMS`：该相机的重投影 RMS；
- `Gizmo Depth`：Scene 窗口相机视锥的显示长度。

相机 FOV 的计算关系为：

```text
HFOV = 2 × atan(ImageWidth  / (2 × FocalLengthPixels))
VFOV = 2 × atan(ImageHeight / (2 × FocalLengthPixels))
```

三台相机使用各自的分辨率和焦距计算，因此不同长宽比不会共用同一个 HFOV 或 VFOV。

如果需要创建真正的 Unity `Camera`：

1. 把 Camera GameObject 的 Transform 设为对应 `CameraPoint3D` 的 Transform；
2. 把 `Camera.fieldOfView` 设为 `VerticalFov`；
3. 把 Camera 的 aspect 设为原图宽度除以高度；
4. 保持 Lens Shift 为 0。

### 11.3 RefPoint3D

每个三维参考点包含：

- `Id`：与三张图片中的 `RefPoint2D.Id` 对应；
- `Reprojection RMS`：该点跨三张图片的重投影误差；
- Transform Position：恢复出的三维坐标。

Scene 窗口中会用黄色 Gizmo 显示三维参考点。

## 12. 坐标系

- Camera 0 位于 `(0, 0, 0)`；
- Camera 0 旋转为 `(0, 0, 0, 1)`；
- Unity 相机观察方向为本地 `+Z`；
- 原生计算机视觉坐标会转换到 Unity 坐标；
- 世界方向由 Camera 0 拍摄方向决定；
- 世界尺度由指定的两点真实距离决定；
- 未提供额外的水平或重力参考，因此结果不保证自动与地面水平。

如果需要让模型的竖直方向与 Unity 世界 Y 轴对齐，可以在求解后整体旋转 `ReconstructionResult`，但不要单独移动某一台相机或某些点。

## 13. 常见失败原因

### 场景中不是三个 RefPicture

删除多余的 `RefPicture`，或补齐缺少的对象。工具会检查所有已加载场景中的有效场景对象。

### Camera ID 重复

确认三个 Camera ID 正好是 0、1、2。

### 点 ID 重复或集合不一致

检查每张图片内部是否有重复 ID，并确认三张图片具有完全相同的 ID 集合。

### 点位于图片矩形外

检查点的 RectTransform 中心是否位于对应 Canvas 的矩形内部，并确认 Canvas 尺寸与照片一致。

### 共面退化

标记点大多位于一个平面。增加位于物体前后不同深度的点。

### 视差不足或极小基线

照片拍摄位置太接近，或者只旋转了相机。需要重新拍摄具有明显位置变化的照片。

### FOV 到达边界

真实 FOV 不在配置范围内，或求解只能把 FOV 推到边界。扩大或修正对应图片的 FOV 范围。

### 重投影误差过高

错误信息会列出误差较大的点 ID。重点检查：

- 三张图中的该 ID 是否确实对应同一个物理点；
- 是否有一张图标到了相邻特征；
- 点是否位于模糊、反光或遮挡区域；
- Canvas 尺寸是否填写错误；
- 图片是否被裁剪或拉伸。

### 候选解歧义

当前三张照片和点分布支持多个相近误差但不同 FOV 的解。可以：

- 增加更准确的非共面点；
- 缩小到合理的 FOV 范围；
- 使用基线更明显的照片；
- 避免三个相机近似共点或纯旋转。

### 找不到 ReconstructionNative.dll

确认文件存在：

```text
Assets/Plugins/x86_64/ReconstructionNative.dll
```

并确认插件导入设置只启用 Windows x86_64 Editor。

## 14. 原生插件重新构建

通常工程中已经包含可直接使用的 DLL，不需要重新构建。

需要修改原生代码或重新生成插件时，安装 Visual Studio 的“使用 C++ 的桌面开发”工作负载，然后在 Unity 工程根目录打开 PowerShell：

```powershell
.\Native\ReconstructionNative\Build-Native.ps1
```

脚本会：

1. 按固定版本获取 PoseLib、Ceres 和 Eigen；
2. 构建 Windows x64 静态依赖；
3. 生成 `ReconstructionNative.dll` 和 PDB；
4. 运行原生合成测试；
5. 把最终文件复制到 `Assets/Plugins/x86_64`。

如果依赖已经离线下载：

```powershell
.\Native\ReconstructionNative\Build-Native.ps1 -DependencyRoot D:\ThirdParty\Reconstruction
```

依赖目录应包含：

```text
Reconstruction
├── PoseLib
├── ceres-solver
└── eigen
```

第三方许可证位于：

```text
Assets/Plugins/x86_64/THIRD_PARTY_NOTICES.md
```

## 15. 推荐工作流程

1. 对照片进行镜头校正并确认没有裁剪或拉伸。
2. 建立三个 Canvas，设置原始像素尺寸。
3. 配置 Camera ID 和合理的 VFOV 范围。
4. 先标记 15～20 个覆盖完整物体的高质量点。
5. 配置 Camera 0 的尺度参考。
6. 执行 Solve。
7. 检查 RMS、三角化角、相机位置和点云形状。
8. 如果误差较高，优先修正错误 ID，而不是盲目增加点。
9. 结果稳定后，再增加更多高质量点并重新 Solve。
10. 需要对齐地面或业务坐标系时，整体调整 `ReconstructionResult`。

## 16. 当前版本不包含的功能

- 自动特征提取和自动点匹配；
- 超过三台相机的 N-view 重建；
- 某个点只在部分照片中可见；
- 径向、切向和鱼眼畸变估计；
- 自动重力或地面方向恢复；
- 稠密点云、表面网格和纹理烘焙；
- Player 运行时求解；
- macOS、Linux、Android 或 iOS 原生插件。
