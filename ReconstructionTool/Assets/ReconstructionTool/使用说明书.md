# Unity 多视图稀疏重建工具使用说明书

## 1. 工具用途

本工具根据至少三张从不同位置、不同相机拍摄的照片，以及人工标记的一一对应参考点和可选参考线，恢复：

- 所有输入相机的拍摄位置和方向；
- 每台相机独立的像素焦距、水平 FOV 和垂直 FOV；
- 所有有效参考点的三维坐标；
- 可见物理直边对应的三维无限直线；
- 依据用户指定距离恢复的绝对尺度；
- 整体、单台相机和单个参考点的重投影误差。

底层使用 PoseLib 2.0.5、Ceres Solver 2.2.0 和 Eigen 3.4.0。当前版本生成相机、稀疏三维点和三维直线，不生成稠密点云或网格。

## 2. 运行条件与限制

- Unity 版本：6000.3.15f1。
- 平台：Windows x64 UnityEditor。
- 至少使用三张照片和三个 `RefPicture`，最多支持 64 个机位。
- Camera 0～2 是基础三视图；Camera 3 及以后是允许局部可见的附加机位。
- Camera 3+ 可以设为 `仅求相机位姿`，只定位该相机而不改变公共三维点和直线。
- 各照片可以来自不同设备，分辨率、长宽比和 FOV 可以不同。
- 使用针孔相机模型，主点固定在图片中心，且 `fx = fy`。
- 不估计径向畸变、切向畸变、非中心主点和滚动快门。
- 不支持鱼眼原图。明显畸变的照片应先完成镜头校正。
- 不支持照片被非等比拉伸、未知裁剪或透视变形。
- 基础参考点必须能在 Camera 0～2 中全部标出；附加机位只标实际可见的基础点，参与公共重建的附加机位还可以共同增加基础三视图完全不可见的新点。
- 基础参考线必须能在 Camera 0～2 中全部标出；附加机位可以不标或只标可见的子集。

## 3. 拍摄照片

### 3.1 拍摄要求

1. 所有照片必须拍摄同一个静止场景或静止物体。
2. 拍摄时应改变相机位置，不能只站在原地旋转相机。
3. 相机之间应具有明显但不过大的平移基线，并保持足够的共同可见区域。
4. 尽量避免运动模糊、失焦、过曝、强反光和透明表面。
5. 保留完整原图，不要对某一张照片单独裁剪或改变长宽比。
6. 如果必须缩放图片，应同时等比缩放整张图片，并让 Canvas 使用缩放后的真实像素尺寸。

一个比较稳定的拍摄方式是：一张正面照片，另外两张分别从左前方和右前方拍摄。物体表面应在三张图中都有足够多的共同可见点。

### 3.2 相机运动要求

Camera 0～2 不要求互相正交，也不要求视角恰好相差 `90°`。工具需要的是不同相机位置产生的平移视差：三个机位保持一定角度差和足够基线，同时保留共同可见区域即可。可以采用一个主视角加左右两个斜视角，也可以让其中一个机位略高或略低。

以下拍摄方式容易导致失败：

- 基础三张照片几乎来自同一个位置；
- 只有旋转，没有平移；
- 相机基线相对于物体距离过小；
- 视角变化过大，导致共同可见点太少；
- 所有标记点都位于同一个平面。

## 4. 创建参考图片 Canvas

场景中必须至少存在三个 `RefPicture`。

对每张照片分别执行：

1. 创建一个 Canvas。
2. 建议把 Canvas 的 Render Mode 设为 `World Space`，方便在 Scene 窗口中同时查看三张图片。
3. 将 Canvas 的 `RectTransform` 宽度和高度设为照片的实际像素宽高。
4. 在 Canvas 同一个 GameObject 上添加 `RefPicture`。
5. 在 Canvas 下创建 `Image` 或 `RawImage` 子对象，用它完整显示照片。
6. 将显示图片的子对象拉伸到 Canvas 全部区域，不要做非等比缩放。

例如：

| Camera ID | 照片尺寸 | Canvas RectTransform |
| --- | --- | --- |
| 0 | 4000 × 3000 | 4000 × 3000 |
| 1 | 1920 × 1080 | 1920 × 1080 |
| 2 | 3024 × 4032 | 3024 × 4032 |

Canvas 可以分别具有不同的 pivot、世界位置、整体旋转和等比缩放。工具会使用 `InverseTransformPoint` 把点转换回图片局部像素坐标。

> Canvas 在 Scene 中显示得很大时，可以整体等比缩小，例如把 Scale 设为 `0.001, 0.001, 0.001`。不要只缩放一个轴。

## 5. 配置 RefPicture

### 5.1 Camera ID

所有 `RefPicture` 的 Camera ID 必须唯一并从 0 连续编号：

- 第一张：`0`
- 第二张：`1`
- 第三张：`2`
- 附加图片：`3、4、5……`

Camera 0～2 用于初始化基础三维结构，必须具有完整的共同点集。Camera 3 及以后可以只拍到场景局部，但每个附加机位至少需要 4 个已经存在于基础点集中的参考点，建议使用 6 个以上。

Camera 0 定义最终重建坐标系：

- Camera 0 的位置固定为世界原点；
- Camera 0 的旋转固定为单位旋转；
- 其他相机和三维点都相对于 Camera 0 输出。

### 5.2 仅求相机位姿

Camera 3 及以后可以勾选 `仅求相机位姿`。Camera 0～2 是基础三视图，不能使用该模式。

启用后的求解顺序为：

1. 该机位不参与公共 `RefPoint3D`、`RefLine3D`、其他相机和整体结构的联合解算；
2. 先由其余参与公共重建的机位完成三维点和三维线；
3. 固定全部已有三维结构；
4. 单独使用当前 Canvas 的 `RefPoint2D` 和可选 `RefLine2D`，优化该相机的位置、旋转和 FOV。

该模式适合只想获得拍摄位置，但不希望局部照片、广角照片或低质量照片把公共结构拉偏的情况。它仍需至少 4 个基础点，建议 6 个以上且分散在画面不同区域；参考线可选。图片、点和线置信度仍会在本机位的单独优化中生效。

仅求位姿的机位不能参与生成新的 `RefPoint3D`。如果它使用 Camera 0～2 不存在的新 Point ID，该点必须先由至少两个没有启用此模式的附加机位共同生成。

### 5.3 垂直 FOV 搜索范围

每个 `RefPicture` 都有独立的：

- 最小垂直 FOV；
- 最大垂直 FOV。

默认范围为 `15°～120°`。如果完全不知道相机参数，可以先保留默认值。

如果能够从 EXIF、设备规格或经验中大致判断 FOV，可以适当缩小范围，例如估计 VFOV 在 50° 左右时设置为 `35°～70°`。更合理的范围可以减少歧义，但真实 FOV 必须处于范围内部，不能刚好卡在边界。

不要把手机厂商给出的对角 FOV 直接当作垂直 FOV。

### 5.4 图片置信度

每个 `RefPicture` 都有独立的 `图片置信度`，范围为 `0.1～1`，默认值为 `1`。

该值是整张图片的全局观测权重，会分别与该图片中每个点或线的置信度相乘：

- `1`：正常使用；
- `0.7～0.9`：轻度广角、压缩较重或标点精度稍差；
- `0.4～0.6`：明显广角或疑似存在一定畸变；
- `0.1～0.3`：仅在无法替换素材时谨慎使用。

例如图片置信度为 `0.6`，某个点的置信度为 `0.5`，该点在此图片中的实际求解权重就是 `0.6 × 0.5 = 0.3`。它们不是相加关系。

至少应保留一张质量较好的图片为 `1`。所有图片都设置为相同的低值不会改善相对权重。置信度不能校正镜头畸变，只能减弱低质量图片对最终结果的影响；设置过低还会削弱多视图约束。

求解后 Console 会逐图片输出 FOV、归一化 RMS、径向残差相关性、广角或畸变嫌疑、最外圈参考点的估计径向偏移，以及可尝试的置信度。诊断只是统计提示：边缘点标错、不同物理点或非刚体变化也可能表现为“疑似畸变”。

### 5.5 最大重投影容差

Camera 0 的 Inspector 提供全局 `最大重投影容差`。它使用归一化像素：每张图片的长边会先缩放为 `1000` 像素，再比较重投影误差。

- 设为 `3`，表示每坐标轴 RMS 容差约为归一化长边的 `3/1000=0.3%`，不是固定的三米或三厘米；
- 对原图长边为 `4000px` 的照片，`3` 相当于约 `12px`；长边为 `1920px` 时约为 `5.76px`；
- 粗略物理换算为 `横向误差≈物距×原图像素误差÷焦距像素`。例如 `4000×3000`、垂直 FOV `60°`、物距 `5m` 时，容差 `3` 约对应 `2.3cm`；物距变成 `10m` 时约为 `4.6cm`；
- 这是 RMS 统计门槛，不是每一个点绝对不能超过的硬性最大距离。物理换算还会随每个点的深度、相机 FOV 和图片尺寸变化。

- `1.5`：默认值，要求严格；
- `2～3`：适合人工标点或压缩图片；
- `3～5`：可用于难以替换的网络素材；
- 大于 `5`：通常只适合作为低精度诊断结果。

例如长边为 `2000` 像素时，归一化容差 `3` 相当于原图约 `6` 像素。提高容差只决定是否接受结果，不会自动修复错误 ID、非刚体变化或镜头畸变。

### 5.6 RawImage 镜头畸变显示修正

工程提供 `RawImageLensDistortionCorrector`，使用 UI Shader 在显示阶段修正桶形、枕形和简单胡须形畸变，不会修改原始 Texture：

1. 将照片放入 `RawImage`；
2. 给同一对象添加 `RawImageLensDistortionCorrector`；
3. 桶形原图从负的 `K1` 开始，例如 `-0.05`；枕形原图使用正值；
4. 普通桶形修正先保持 `K2=0`，只有边缘方向发生反转时再少量调整 `K2`；
5. `畸变中心` 通常保持 `(0.5, 0.5)`，只有镜头中心明显偏移时才修改；
6. 修正后出现透明边缘时，提高 `修正后缩放` 进行裁切。

建议观察靠近画面边缘、本应笔直且不穿过画面中心的物理直线，逐步调整参数直到它恢复为直线。不要只观察经过中心的对角线，因为径向畸变下这类线可能仍然保持笔直。

如果该 RawImage 用于重建标点：

- RawImage 与 `RefPicture` 的 RectTransform 应保持相同尺寸和位置，不要非等比拉伸；
- 开启或修改修正参数后，应按照修正后的显示位置重新摆放 `RefPoint2D` 和 `RefLine2D`；
- Shader 只负责显示修正，不会把 `K1/K2` 直接传给原生求解器；求解器读取的是修正画面坐标中重新标记的点和线；
- `修正后缩放` 会改变有效视场，求解器会重新估计 FOV，但仍应给出合理的 MinFOV/MaxFOV 范围。

## 6. 创建和标记 RefPoint2D

### 6.1 创建参考点

在每个 Canvas 下创建若干 UI 子对象：

1. 子对象必须具有 `RectTransform`。
2. 添加 `RefPoint2D`。
3. 设置整数 `Id`。
4. 将对象中心移动到照片中的目标位置。
5. 可以添加小尺寸 `Image` 作为十字、圆点或其他视觉标记。

同一个物理点在任何照片中都必须使用完全相同的 ID。

例如，物体左上角在三张图中都使用 ID `100`，右下角都使用 ID `101`。

### 6.2 ID 规则

- 同一张照片内不能存在重复 ID。
- Camera 0～2 的 `RefPoint2D` 数量和 ID 集合必须完全相同。
- Camera 0～2 中相同 ID 必须表示同一个物理点；仅仅数量相等但 ID 或物理位置不对应是不允许的。
- 每个 Camera 3+ 至少需要 4 个基础点，用于先恢复该附加相机的位姿和 FOV。
- Camera 3+ 可以增加基础点集中不存在的新 ID，但同一个新 ID 必须至少被两个附加机位标记，并表示同一个物理点。
- 用于生成新 ID 的两个附加机位都必须参与公共重建，`仅求相机位姿` 的机位不能计入。
- 附加新点不能计入相机初始化所需的 4 个基础点；只有一个机位看到的新点无法确定三维深度。
- ID 可以不连续，也可以使用负数，但建议使用容易管理的正整数。
- Camera 0 的尺度参考 ID 也必须存在于这个共同 ID 集合中。

### 6.3 参考点置信度

每个 `RefPoint2D` 都有独立的 `Confidence`，范围为 `0.1～1`，默认值为 `1`。它只影响“这个物理点在当前这张图片里的观测”，因此同一 Point ID 在不同图片中可以设置不同值。

- `1`：位置清晰、可以准确标定；
- `0.7～0.9`：轻微模糊、遮挡或只能大致定位；
- `0.4～0.6`：定位明显不可靠，但仍希望保留；
- 若无法确认是不是同一个物理点，应删除或改正该点，不要依靠低置信度掩盖错误 ID。

点、线与图片置信度使用相乘关系：

```text
点观测权重 = 图片置信度 × RefPoint2D Confidence
线观测权重 = 图片置信度 × RefLine2D Confidence
```

这些值是优化中的相对权重，不是“正确概率”，也不会叠加。求解器还会使用鲁棒损失抑制特别大的残差；质量诊断仍会保留原始误差信息，避免低置信度把明显错误完全隐藏。

### 6.4 点的数量

- 最少需要 8 个共同点。
- 少于 15 个点时工具会显示低稳定性警告。
- 通常建议使用 20～50 个高质量点。

数量不是唯一标准。点的准确性、空间覆盖和深度分布更重要。

### 6.5 选点建议

优先选择：

- 清晰、尖锐并且能精确重复定位的角点；
- Camera 0～2 中都可见且未被遮挡的结构；
- 分布在图片四周和中心的点；
- 同时包含物体前部、中部和后部的非共面点；
- 能明确判断为同一个物理位置的细节。

避免选择：

- 大面积平面上没有明显特征的位置；
- 模糊轮廓或阴影边缘；
- 反光、透明或会随视角变化的位置；
- 重复纹理中容易混淆的点；
- 被遮挡后只能凭猜测标出的位置；
- 只有屏幕坐标相近、实际并非同一物理点的位置。

建议在放大照片后标点。少量高精度点通常优于大量随意标记的点。

### 6.6 定义参考点连线

连线关系只在 Camera 0 的 `RefPicture` 中定义：

1. 展开 `参考点连线（Camera 0） > 连线关系`；
2. 添加数组元素；
3. 为每条连线填写 `起点 ID` 和 `终点 ID`。

同一份 ID 关系会在每张图片中连接本机位实际存在的两个 `RefPoint2D`，不会跨 Canvas 连线；附加机位缺少任一端点时会跳过该条二维连线。Solve 成功时，每组关系都会生成一个独立的 `RefPointConnection3D`，直接持有两个 `RefPoint3D`；之后隐藏或删除 Canvas 不会影响三维连线。

二维连线显示为青色，三维连线显示为橙色。若某个 ID 不存在，该条连线会跳过。

### 6.7 创建参与解算的参考线

`参考点连线` 只是可视化关系，不参与求解。真正用于提高解算精度并生成三维线的是 `RefLine2D`。

对一条三张图片都能看清的物理直边：

1. 在每个 `RefPicture` Inspector 中点击 `创建 RefLine2D`；
2. 三张图片中的这三条组件填写相同的 `Id`；
3. 移动、旋转并调整其 `RectTransform` 宽度，让粉色操作段准确贴合图片中的直边；
4. 不需要把操作段两端放到实际端点，三张图的端点也不需要互相对应；
5. 如果某张图中的线较模糊，可降低该 `RefLine2D` 的 `Confidence`。

SceneView 中粗粉色段是操作手柄，粉色虚线表示实际送入求解器的整条二维无限直线。操作段越长，方向越容易标准；归一化长度小于 20 像素会被拒绝。

参考线的规则：

- 同一张图片内 Line ID 不能重复；
- 参考线是可选约束；完全不使用时，Camera 0～2 都保持 0 条即可；
- 使用参考线时，Camera 0～2 的 `RefLine2D` 数量和 Line ID 集合必须完全相同；
- 上一条只约束 Camera 0～2；Camera 3+ 可以使用基础 Line ID 的任意子集，也可以不标线；
- 仅求相机位姿的 Camera 3+ 可以使用参考线定位自己，但不会参与生成或调整对应 `RefLine3D`；
- 相同 Line ID 必须表示同一条物理直线；
- 三个主机位中的操作段端点不需要一一对应，因为 `RefLine2D` 表达的是物理无限直线，端点只用于调整二维位置和方向；
- 参考线可辅助约束相机姿态、FOV 和结构方向，但不能替代至少 8 个参考点；
- 线必须来自静止、刚性的真实直边，避免阴影边缘、曲线、反光轮廓和随视角变化的边界。

求解器会先使用 Camera 0～2 的二维线生成基础三维无限直线。附加相机完成点式 P4Pf 初始定位后，会立即使用本机位实际标出的这些参考线细化位置、旋转和 FOV；随后所有参与公共重建的机位再联合优化三维线、相机和参考点。仅求相机位姿的机位也会在三维线固定后使用它定位自己。

### 6.8 使用参考线定义结果 X 轴

需要让重建结果具有明确的水平方向时，可以在代表水平结构的一条 `RefLine2D` 上勾选 `作为结果 X 轴`。

- 可以在该物理直线任意一个机位的 `RefLine2D` 副本上勾选；
- 同一个 Line ID 在多个机位重复勾选不会冲突；
- 整个场景最多只能指定一个不同的 Line ID 作为 X 轴；
- Solve 成功后会整体旋转普通的 `ReconstructionResult` 根节点，使对应 `RefLine3D` 与世界 X 轴平行；
- 三维无限直线没有固有正方向，因此 `+X` 和 `-X` 等效，工具会选择旋转量较小的一端；
- 该设置只对齐直线方向，不会把直线强制平移到世界原点；
- 一条直线只能确定 X 轴方向，不能同时唯一确定世界上方向；工具会用最小旋转尽量保留原有朝向。

启用该选项后，Camera 0 仍位于结果原点，并保持相对于 `ReconstructionResult` 根节点的本地单位旋转；它的世界旋转会随结果根节点一起改变。没有勾选任何参考线时，输出行为与原来完全一致。

## 7. 配置绝对尺度

绝对尺度只在 Camera 0 的 `RefPicture` 上配置：

- 参考点 ID A；
- 参考点 ID B；
- 两点的真实距离。

两个 ID 必须不同，且都存在于 Camera 0～2 的基础点集中。真实距离必须大于 0。

输出单位由填写的真实距离决定：

- 如果填写米，输出位置单位就是米；
- 如果填写厘米，输出位置单位就是厘米；
- 如果希望 1 Unity unit 表示 1 米，就应使用米填写距离。

建议选择：

- 实际距离较大；
- 能够准确测量；
- 两端容易在照片中精确定位；
- 不会因物体弯曲或遮挡产生歧义；
- 尽量不要选择两个非常接近的点。

## 8. 输入检查清单

点击 Solve 前确认：

- 场景中至少有三个 `RefPicture`；
- Camera ID 从 0 开始连续且没有重复或缺号；
- Canvas 宽高比与完整照片一致，且图片铺满对应矩形；
- 照片没有被非等比拉伸或未知裁剪；
- 每张照片中的 ID 都不重复；
- Camera 0～2 具有完全相同的 ID 集合；
- 每个 Camera 3+ 至少具有 4 个基础点；
- `仅求相机位姿` 只用于 Camera 3+；
- 每个附加新 ID 至少出现在两个参与公共重建的附加机位中，并具有足够视差；
- 至少有 8 个共同点，建议 15 个以上；
- 所有点都位于对应图片矩形内；
- 点具有明显的非共面深度；
- Camera 0 的尺度 ID 正确；
- 尺度真实距离和单位正确；
- Camera 0～2 之间具有明显平移视差。
- 若使用参考线，三张图片具有完全相同的 Line ID 集合，且每条操作段已准确贴边。

## 9. 执行 Solve

1. 在 Hierarchy 中选中任意一个带有 `RefPicture` 的 Canvas。
2. 在 Inspector 底部点击 `Solve`。
3. 无论在哪个 `RefPicture` 上点击，工具都会查找场景中的全部 `RefPicture`。
4. 尺度配置始终读取 Camera 0。
5. 输入验证和原生求解都成功后，工具才会创建新结果。

求解失败时不会删除或替换旧的 `ReconstructionResult`。

再次 Solve 成功时：

- 先完整求出新结果；
- 再替换旧结果；
- 整个替换过程可以使用一次 Unity Undo 撤销。

## 11. 查看求解结果

### 11.1 普通结果根节点

`ReconstructionResult` 只是用于整理层级的普通 GameObject，不挂载 `ReconstructionResult` 或其他汇总脚本。所有几何对象由自己的组件和 Transform 自行表达：

- `CameraPoint3D` 自己保存相机参数；
- `RefPoint3D` 自己保存 ID、位置和点误差；
- `RefPointConnection3D` 自己保存两个端点引用；
- `RefLine3D` 使用自己的位置和 Forward 表达三维无限直线。

整体点 RMS、线 RMS、尺度倍率、三角化角和原生版本会在 Solve 成功日志中输出。判断建议：

- RMS 越低越好；
- 中值三角化角过小通常表示相机基线不足；
- 工具在三角化角低于安全阈值或误差过高时会直接拒绝结果；
- 数值通过校验并不代表点一定具有正确物理含义，仍应在 Scene 中检查相机和点云形状。

### 11.2 CameraPoint3D

每个相机对象包含：

- `Camera ID`：从 0 开始的连续机位编号；
- `Source Picture`：对应的 `RefPicture`；
- `Focal Length Pixels`：恢复出的像素焦距；
- `Horizontal Fov`：水平 FOV，单位为度；
- `Vertical Fov`：垂直 FOV，单位为度；
- `Reprojection RMS`：该相机的重投影 RMS；
- `Gizmo Depth`：Scene 窗口相机视锥的显示长度。

相机 FOV 的计算关系为：

```text
HFOV = 2 × atan(ImageWidth  / (2 × FocalLengthPixels))
VFOV = 2 × atan(ImageHeight / (2 × FocalLengthPixels))
```

所有相机使用各自的分辨率和焦距计算，因此不同长宽比不会共用同一个 HFOV 或 VFOV。

如果需要创建真正的 Unity `Camera`：

1. 把 Camera GameObject 的 Transform 设为对应 `CameraPoint3D` 的 Transform；
2. 把 `Camera.fieldOfView` 设为 `VerticalFov`；
3. 把 Camera 的 aspect 设为原图宽度除以高度；
4. 保持 Lens Shift 为 0。

### 11.3 RefPoint3D

每个三维参考点包含：

- `Id`：与输入图片中的 `RefPoint2D.Id` 对应；
- `Reprojection RMS`：该点跨所有可见机位的重投影误差；
- Transform Position：恢复出的三维坐标。

Scene 窗口中会用黄色 Gizmo 显示三维参考点。

### 11.4 RefPointConnection3D

每条三维参考点连线都是独立的 `RefPointConnection3D`，直接引用两个 `RefPoint3D`。它不读取 Canvas，也不读取结果根节点脚本；移动或旋转整个层级时会自然跟随两个端点。

### 11.5 RefLine3D

每条求解成功的参考线会在 `ReconstructionResult/Lines` 下生成一个 `RefLine3D`：

- `Id`：与输入图片中的 `RefLine2D.Id` 对应；
- Transform 的本地 `+Z / Forward`：三维无限直线方向；旋转根节点时会随层级一起旋转；
- `Direction`：当前 `transform.forward` 的只读世界方向；
- Transform Position：直线上的一个代表点；
- `Reprojection RMS`：该线投回所有可见原图后的像素误差；
- `Gizmo Length`：只控制 SceneView 显示长度，不代表真实端点。

橙色 Gizmo 只是对无限直线的有限长度展示。因为输入端点不表示物理端点，所以工具不会虚构三维起点和终点。

## 12. 坐标系

- Camera 0 位于 `(0, 0, 0)`；
- 默认情况下 Camera 0 的世界旋转为 `(0, 0, 0, 1)`；启用参考线 X 轴对齐时，其相对于 `ReconstructionResult` 的本地旋转仍为单位旋转；
- Unity 相机观察方向为本地 `+Z`；
- 原生计算机视觉坐标会转换到 Unity 坐标；
- 世界方向由 Camera 0 拍摄方向决定；
- 世界尺度由指定的两点真实距离决定；
- 未提供额外的水平或重力参考，因此结果不保证自动与地面水平。

如果需要让模型的竖直方向与 Unity 世界 Y 轴对齐，可以在求解后整体旋转 `ReconstructionResult`，但不要单独移动某一台相机或某些点。

## 13. 常见失败原因

### 场景中少于三个 RefPicture

补齐至少三个 `RefPicture`。工具会检查所有已加载场景中的有效场景对象。

### Camera ID 重复

确认所有 Camera ID 唯一，并从 0 连续编号到最后一个机位。

### 附加机位无法初始化

Camera 3+ 至少需要 4 个来自基础点集的可见点。四点是 P4Pf 的最小解，因此参考线不能代替这 4 个点；但 P4Pf 找到初始解后，附加机位实际标出的参考线会参与固定结构细化，并影响本机位的位置、旋转和 FOV。

初始化使用鲁棒内点筛选，不再要求恰好 6 个点时 6 个全部通过：6 个基础点允许其中 1 个未通过初始化内点筛选，最终结果仍必须通过全局重投影容差。四点模式没有离群冗余，任一点标错、四点近似共线或集中在很小区域仍可能失败或多解。

新的错误信息会显示求解器实际识别到的“基础点数量”和“参考线数量”。如果 Inspector 中看起来有 6 个以上点，但日志数量更少，通常表示其中一些是 Camera 0～2 没有的新 ID；这些点不能用于附加相机的首次 P4Pf 初始化。还应检查 FOV 范围、点是否覆盖画面、Canvas 是否裁剪或拉伸，以及 Line ID 是否确实对应相同物理直线。

### 仅求相机位姿失败

该模式仍需先用至少 4 个基础点初始化相机，然后在固定三维结构上优化本机位。检查点 ID 是否已存在于公共三维结果、点是否分散、FOV 范围是否合理，以及图片是否被裁剪或拉伸。增加清晰参考线可以辅助本机位定位，但不能替代至少 4 个基础点。

### 附加新点无法生成

基础三视图不可见的新 ID 必须至少出现在两个参与公共重建的附加机位中。仅求相机位姿的机位不能计入这两个机位。两个机位应从不同位置观察该点并具有足够平移视差；如果只有一个机位、两个机位近似共点或只在原地旋转，就无法确定该点的三维深度。每个相关附加机位仍需另外标出至少 4 个基础点来初始化相机。

### 点 ID 重复或集合不一致

检查每张图片内部是否有重复 ID；Camera 0～2 必须具有完全相同的基础 ID 集合。Camera 3+ 可以使用基础集合的子集，并可共同增加新 ID，但每个新 ID 至少需要两个参与公共重建的附加机位提供一一对应观测。

### 点位于图片矩形外

检查点的 RectTransform 中心是否位于对应 Canvas 的矩形内部，并确认 Canvas 尺寸与照片一致。

### 共面退化

标记点大多位于一个平面。增加位于物体前后不同深度的点。

### 视差不足或极小基线

照片拍摄位置太接近，或者只旋转了相机。需要重新拍摄具有明显位置变化的照片。

### FOV 到达边界

真实 FOV 不在配置范围内，或求解只能把 FOV 推到边界。扩大或修正对应图片的 FOV 范围。

### 重投影误差过高

错误信息会列出误差较大的点 ID。重点检查：

- 三张图中的该 ID 是否确实对应同一个物理点；
- 是否有一张图标到了相邻特征；
- 点是否位于模糊、反光或遮挡区域；
- Canvas 尺寸是否填写错误；
- 图片是否被裁剪或拉伸。

Console 还会输出逐图片诊断：

- `总判断`：直接指出当前主要有问题的图片，以及它比另外图片差多少；
- `偏差最大的点`：列出最应优先检查的 RefPoint ID 和原图像素偏差；
- `更像什么`：区分少数点标错、整图裁剪/尺寸偏移、普遍对应错误或镜头畸变；
- `HFOV / VFOV / DFOV`：水平、垂直和对角 FOV；
- `RMS`：该图片在长边 `1000` 像素下的归一化误差及原图像素误差；
- `径向相关`：误差是否随画面半径呈同方向变化；
- `边缘/中心残差`：边缘点是否明显比中心点更差；
- `畸变估计`：逐图片给出高/中/低证据、最外圈参考点的系统性径向偏移像素、占图片长边比例以及桶形/枕形倾向；
- `配置置信度` 和建议置信度。

“畸变估计”是根据解算后参考点残差拟合出的统计值，不是相机标定得到的真实镜头参数。至少需要 5 个覆盖中心到边缘的点才能给出粗略估计，8 个以上更可靠；点位标错、裁剪、拉伸、物体变化或多张图片具有相似畸变都可能让估计失真。

“超广角”本身不代表图片一定不可用。经过镜头校正、仍符合针孔模型的广角图片可以参与重建；全景拼接、鱼眼或边缘残差明显径向增长的图片风险更高。

若参考线超出容差，Console 会逐条输出 `Camera 编号「Canvas 名称」 / Line ID`、归一化误差、原图像素误差、容差和组合置信度。只需优先调整明确列出的 Canvas 中对应的 `RefLine2D`。平行参考线允许使用；该错误表示生成的三维线投影回指定 Canvas 后，没有贴合所标记的二维线，而不是线与线之间的平行筛查。还应检查相同 Line ID 是否始终对应同一条物理直边，尤其不要在不同图片中对调两条相邻平行边。

### 候选解歧义

当前基础三张照片和点分布支持多个相近误差但不同 FOV 的解。可以：

- 增加更准确的非共面点；
- 缩小到合理的 FOV 范围；
- 使用基线更明显的照片；
- 避免三个相机近似共点或纯旋转。

### 找不到 ReconstructionNative_1_8.dll

确认文件存在：

```text
Assets/Plugins/x86_64/ReconstructionNative_1_8.dll
```

并确认插件导入设置只启用 Windows x86_64 Editor。

## 14. 原生插件重新构建

通常工程中已经包含可直接使用的 DLL，不需要重新构建。

需要修改原生代码或重新生成插件时，安装 Visual Studio 的“使用 C++ 的桌面开发”工作负载，然后在 Unity 工程根目录打开 PowerShell：

```powershell
.\Native\ReconstructionNative\Build-Native.ps1
```

脚本会：

1. 按固定版本获取 PoseLib、Ceres 和 Eigen；
2. 构建 Windows x64 静态依赖；
3. 生成 `ReconstructionNative_1_8.dll` 和 PDB；
4. 运行原生合成测试；
5. 把最终文件复制到 `Assets/Plugins/x86_64`。

如果依赖已经离线下载：

```powershell
.\Native\ReconstructionNative\Build-Native.ps1 -DependencyRoot D:\ThirdParty\Reconstruction
```

依赖目录应包含：

```text
Reconstruction
├── PoseLib
├── ceres-solver
└── eigen
```

第三方许可证位于：

```text
Assets/Plugins/x86_64/THIRD_PARTY_NOTICES.md
```

## 15. 推荐工作流程

1. 对照片进行镜头校正并确认没有裁剪或拉伸。
2. 建立至少三个 Canvas，设置原始像素尺寸。
3. 连续配置 Camera ID 和合理的 VFOV 范围。
4. 先在 Camera 0～2 标记 15～20 个覆盖完整物体的高质量共同点。
5. 在 Camera 3+ 中复制实际可见的基础点，建议每张 6～15 个，最低 4 个。
6. 对只想获取拍摄位置的 Camera 3+，勾选 `仅求相机位姿`。
7. 若要增加基础三视图不可见的新点，在至少两个参与公共重建的附加机位中使用相同新 ID 标记。
8. 对端点不明确但方向清晰的共同直边添加少量高质量参考线。
9. 配置 Camera 0 的尺度参考。
10. 执行 Solve。
11. 检查点 RMS、线 RMS、三角化角、相机位置和点线形状。
12. 如果误差较高，优先修正错误 ID，而不是盲目增加点或线。
12. 结果稳定后，再增加更多高质量约束并重新 Solve。
13. 需要对齐地面或业务坐标系时，整体调整 `ReconstructionResult`。

## 16. 当前版本不包含的功能

- 自动特征提取和自动点匹配；
- Camera 0～2 中某个基础点只在部分照片中可见；
- 径向、切向和鱼眼畸变估计；
- 自动重力或地面方向恢复；
- 稠密点云、表面网格和纹理烘焙；
- Player 运行时求解；
- macOS、Linux、Android 或 iOS 原生插件。
